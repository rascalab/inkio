# 실시간 협업

`@inkio/collab`는 Yjs 기반 실시간 협업을 Inkio 에디터에 연결하는 독립 패키지입니다.
서버는 포함하지 않습니다. 클라이언트(문서 동기화·presence)와 와이어 프로토콜만 제공하고,
서버는 직접 구현하거나 `examples/collab-server` 참조 구현에서 출발하세요.

## 설치

```bash
pnpm add @inkio/collab yjs y-protocols socket.io-client
```

`yjs`·`y-protocols`·`socket.io-client`는 external이라 호스트 앱과 단일 복사본을 공유합니다.
오프라인 저장이 필요하면 `y-indexeddb`를 추가하세요.

## 방 만들기

Next.js App Router에서는 에디터가 클라이언트 컴포넌트 안에 있어야 합니다.

```tsx
'use client';

import { useInkioCollaborativeEditor, CollabPresence } from '@inkio/collab';
// `@tiptap/react`는 직접 설치해야 하며, 버전은 Inkio가 의존하는 Tiptap
// 버전과 맞추세요 (불일치 시 에디터 인스턴스 호환이 깨집니다).
import { EditorContent } from '@tiptap/react';

export function Room({ docId, token }: { docId: string; token: string }) {
  const { editor, provider, status } = useInkioCollaborativeEditor({
    docId,
    url: 'http://localhost:3123/inkio-collab',
    token,
    user: { name: 'Ada', color: '#ff0077' },
    initialContent: '<p>Start here</p>',
  });
  if (!editor) return null;
  return (
    <>
      <span>{status}</span>
      <CollabPresence provider={provider} />
      <EditorContent editor={editor} />
    </>
  );
}
```

훅이 대신 처리하는 규칙:

- 협업 모드에서는 `history`/`undoRedo` 확장을 제거합니다 (Yjs undo와 충돌).
  다른 기본 확장을 넘기거나, 생략하면 core 기본값을 사용합니다.
- `initialContent`는 첫 동기화 이후 문서가 비어 있을 때 단 한 번만 심습니다.
  공유 문서와 `content`를 함께 쓰지 마세요.
- transport 옵션(`socket`, `url`, `token`)은 `docId` 마운트 시 1회만 읽습니다.
  토큰 로테이션은 매 join마다 재평가되는 함수로 전달하세요.

## 기존 소켓 재사용

이미 socket.io-client 소켓을 가진 앱은 새로 연결하지 않고 얹을 수 있습니다.
남의 소켓은 끊지 않습니다.

```ts
import { SocketIOCollabProvider } from '@inkio/collab';

// existingSocket must already be connected to the /inkio-collab namespace:
// the engine listens nowhere else.
const provider = new SocketIOCollabProvider({ docId, socket: existingSocket, token });
provider.connect();
```

## 서버

프로토콜 단일 소스: `@inkio/collab/protocol` 서브패스
(`inkio:collab:join/init/update/awareness/error`, 네임스페이스 `/inkio-collab`).
의존성이 없어 Node 서버에서 React 엔트리 없이 import할 수 있습니다.

`examples/collab-server`는 NestJS 참조 구현입니다 (배포하지 않음).

- `CollabSyncEngine`: room = docId 릴레이, `verify` 인증 훅, 스로틀 `onPersist` 훅.
- `InkioCollabModule.forRoot(options)`: NestJS 다이나믹 모듈.
- `InkioCollabModule.attachToExistingServer(server, options)`: 기존 socket.io 서버에 얹기.

```bash
pnpm --filter example-collab-server build
pnpm --filter example-collab-server start
pnpm --filter example-collab-server smoke
```

### 인증 걸기

`verify`는 매 join마다 (같은 방 재입장 포함) 호출됩니다. 토큰 로테이션을
쓰려면 클라이언트에서 함수형 토큰을 넘기세요.

```ts
InkioCollabModule.forRoot({
  verify: async (token, docId) => checkAccess(token, docId),
  maxRooms: 1000, // 미지정 시 무제한 (개발용 기본값)
});
```

### 에러 코드

서버가 보내는 `inkio:collab:error` 코드와 의미입니다.

| 코드 | 의미 | 클라이언트 상태 |
|------|------|------|
| `unauthorized` | `verify`가 거부 | `unauthorized` |
| `forbidden` | `maxRooms` 초과 | `unauthorized` (입장 실패) |
| `internal` | `verify`가 throw | 그대로 |
| `invalid-message` | 깨진 프레임 (무시됨) | 그대로 |
| `rate-limited` | 초당 릴레이 예산 초과 (버려짐) | 그대로 |

### 멀티룸과 재접속

소켓 하나가 여러 방에 들어갈 수 있습니다. 재접속 후 같은 방에 다시
join해도 `verify`가 다시 실행되므로, 회수된 토큰은 그 시점부터 차단됩니다.

## 오프라인과 presence

```ts
import { persistDocToIndexedDB } from '@inkio/collab';
const persistence = persistDocToIndexedDB(docId, doc);
// ...
persistence.destroy(); // 언마운트 시 반드시 호출 (IDB 연결 누수 방지)
```

> 하나의 `docId`에 live persistence를 둘 이상 열지 마세요. 스냅샷을 한 번만
> 읽고 끝내려면 타임아웃 내장된 `loadIndexedDBState(docId, doc)`를 쓰세요.

awareness 상태는 `{ user: { name, color } }`를 싣습니다. `CollabPresence`가 접속자 목록을
그리고, `useCollabPeers(provider)`로 직접 받을 수도 있습니다. 에디터 내 원격 캐럿은
지원하지 않습니다. Tiptap v3의 협업 바인딩이 동기화 플러그인 키를 비공개로 들고 있어
`y-prosemirror` 커서 플러그인을 장착할 수 없기 때문입니다.
