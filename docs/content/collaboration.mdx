# 실시간 협업

`@inkio/collab`는 Yjs 기반 실시간 협업을 Inkio 에디터에 연결하는 패키지입니다.
전송 계층은 [Hocuspocus](https://tiptap.dev/docs/hocuspocus/introduction)를 씁니다.
표준 Yjs sync 프로토콜이라 재접속 때 차이만 주고받고, presence·인증·읽기 전용·저장은
서버가 책임집니다. 서버는 `examples/collab-server` 참조 구현에서 출발하세요.

## 설치

```bash
pnpm add @inkio/collab yjs
```

`yjs`·`@hocuspocus/*`·`y-indexeddb`는 external이라 호스트 앱과 단일 복사본을 공유합니다.

## 방 만들기

Next.js App Router에서는 에디터가 클라이언트 컴포넌트 안에 있어야 합니다.

```tsx
'use client';

// EditorContent는 @inkio/collab이 재노출합니다. @tiptap/react를 따로 설치하지 마세요.
import { useInkioCollaborativeEditor, CollabPresence, EditorContent } from '@inkio/collab';

export function Room({ docId, token, accountId }: { docId: string; token: string; accountId: string }) {
  const { editor, provider, status, readOnly } = useInkioCollaborativeEditor({
    docId,
    url: 'ws://127.0.0.1:3123/collab',
    token,
    user: { name: 'Ada', color: '#ff0077' },
    content: '<p>Start here</p>',
    offline: { accountId, deploymentId: 'local-notebook' },
  });
  return (
    <>
      <span role="status">{status}{readOnly ? ' (읽기 전용)' : ''}</span>
      <CollabPresence provider={provider} />
      {editor && <EditorContent editor={editor} />}
    </>
  );
}
```

훅이 대신 처리하는 규칙:

- 협업 모드에서는 `history`/`undoRedo` 확장을 제거합니다 (Yjs undo와 충돌).
  `extensions`를 생략하면 core 기본값을, 빈 배열이면 최소 문서 스키마를 씁니다.
- 원격 사용자의 캐럿과 선택 영역을 에디터 안에 그립니다 (별도 CSS 불필요).
- `content`는 쓰기 권한으로 동기화된 빈 문서에만 넣는 시드입니다. 모든 클라이언트에서
  같은 스키마·필드·시드를 넘기면 동시 접속해도 한 벌로 합쳐집니다. 서로 다른 시드는
  별개 콘텐츠로 합쳐질 수 있습니다. 앱 버전이 섞이는 환경에서는 서버에서 한 번만 심으세요.
- `token`은 인증할 때마다 다시 읽습니다. 이미 거부된 문자열 토큰을 바꾸면 에디터를 다시
  만들지 않고 그 문서만 재시도합니다. 토큰 콜백을 갱신한 뒤에는
  `retryCollabAuthentication(provider)`로 즉시 재시도할 수 있습니다.
- `docId`·`url`·공유 소켓·오프라인 계정/배포 범위가 바뀌면 세션을 새로 만듭니다.
- 쓰기 권한으로 동기화되기 전에는 편집할 수 없습니다. 서버가 읽기 전용 권한을 주면
  `readOnly`가 `true`입니다. 오프라인 저장을 켠 기존 쓰기 세션은 네트워크 단절 중에
  편집할 수 있지만, 캐시만 불러온 새 세션은 온라인 권한을 확인할 때까지 읽기 전용입니다.
- React StrictMode의 이중 마운트에서도 안전합니다 (provider는 effect 안에서 생성·정리).

`status`는 `connecting` → `synced`, 끊기면 `disconnected`입니다. `unauthorized`일 때는
에디터가 반환되지 않습니다. 토큰 공급·권한 조회·스냅샷 불러오기가 일시적으로 실패한
경우에는 해당 문서만 지수 백오프로 재시도합니다. 명시적으로 거부된 경우에는 자격 증명을
갱신하세요.

## 여러 문서를 한 소켓으로

같은 Hocuspocus v4 서버에서 여러 문서를 열 때는 소켓 하나를 공유할 수 있습니다.
서버가 다르면 소켓도 따로 만드세요. 권한은 문서별로 확인합니다.

```ts
import { HocuspocusProviderWebsocket, useInkioCollaborativeEditor } from '@inkio/collab';

const socket = new HocuspocusProviderWebsocket({ url: 'ws://127.0.0.1:3123/collab' });
// 각 문서 컴포넌트에서
useInkioCollaborativeEditor({ docId, token, websocketProvider: socket });
```

## 서버

`examples/collab-server`는 배포용 패키지가 아닌 로컬 참조 구현입니다. CLI는 기본적으로
루프백에만 바인딩하며, 데이터 디렉터리와 문서별 접근 설정을 명시하지 않으면 시작하지
않습니다. 기본 Nest 모드는 `ws://127.0.0.1:3123/collab`, 단독·분리 sync 모드는
`ws://127.0.0.1:3123`에 연결합니다. 운영 연결은 `wss://`를 사용하세요.

참조 CLI는 `COLLAB_ROOM_ID`로 지정한 **한 방**에만 접근을 허용합니다.
`COLLAB_EDITOR_TOKEN`은 쓰기, 선택적인 `COLLAB_VIEWER_TOKEN`은 읽기 자격 증명입니다.
방 생성·목록, 관리자 화면, 계정 관리나 토큰 발급 API는 제공하지 않습니다.
다중 문서 서비스에서는 앱의 인증과 문서 ACL을 `verify`에 연결하세요.
GitHub Pages 같은 정적 호스트는 WebSocket 서버를 실행하지 않으므로 sync를
별도의 Node.js 호스트에 배포해야 합니다.

```bash
pnpm --filter example-collab-server build
mkdir -p examples/collab-server/data
export DATA_DIR="$PWD/examples/collab-server/data"
export COLLAB_ROOM_ID=shared-doc
export COLLAB_EDITOR_TOKEN="$(openssl rand -hex 32)"
pnpm --filter example-collab-server start
```

연결할 때 `docId: 'shared-doc'`와 발급한 문서 토큰을 사용합니다. 모드별 동기화·권한·
재시작 복원 검사는 `pnpm --filter example-collab-server smoke`로 실행할 수 있습니다.

### NestJS에 임베드

Nest 앱과 같은 HTTP 서버·포트를 쓰며, WebSocket 경로는 기본 `/collab`입니다.
`dataDir`은 미리 만든 비공개 디렉터리, `verify`는 필수입니다.

```ts
@Module({
  imports: [
    InkioCollabModule.forRoot({
      dataDir: './data',
      verify: (token, docId, request) => access.checkDocument(token, docId, request),
      allowedOrigins: ['https://app.example.com'], // 브라우저 앱의 실제 Origin
    }),
  ],
})
export class AppModule {}

const app = await NestFactory.create(AppModule);
app.enableShutdownHooks(); // 종료 시 대기 중인 저장을 flush
await app.listen(3123, '127.0.0.1');
```

클라이언트는 `url: 'ws://127.0.0.1:3123/collab'`로 접속합니다. 서비스를 통해 문서를
직접 변경하려면 `INKIO_HOCUSPOCUS`를 주입받아 `openDirectConnection(docId)`를 쓰되,
이 경로는 소켓 인증을 우회하므로 서비스에서 직접 권한을 확인하세요.
Nest 밖에서는 `attachHocuspocus(httpServer, hocuspocus)`를 쓸 수 있습니다.

### 문서별 권한과 분리 운영

`verify(token, docId, request)`는 토큰에서 사용자를 확인한 뒤 그 사용자의 테넌트와 문서
멤버십까지 검사해야 합니다. 토큰이나 문서 ID만 유효하다고 허용하지 마세요.
`'write'`는 편집, `'read'`는 서버가 쓰기를 거부하는 읽기 전용, `false`는 거부입니다.
의존 서비스에 장애가 나면 예외를 던지세요. 명시적 접근 거부와 구분되지만 접근은 차단됩니다.
권한이 바뀌면 기존 세션을 닫아 다시 인증하도록 하세요.

분리 모드에서 sync는 `VERIFY_URL`의 비공개 `POST /collab/verify`에 `{ token, docId }`를
보냅니다. API는 별도의 `COLLAB_VERIFY_KEY`로 sync 호출을 인증하고 문서별 ACL 판단을
`{ access: 'write' | 'read' | false }`로 돌려줍니다. API 포트와 서비스 키는 클라이언트에
노출하지 마세요. 호스트 간 통신에는 HTTPS를 사용하고, 브라우저 Origin을 운영 프록시와
`COLLAB_ALLOWED_ORIGINS`로 제한하세요. 요청·연결 빈도와 사용자별 문서 수 제한도
배포 환경에서 적용하세요.

운영 프록시가 WebSocket 업그레이드를 전달하는지 확인하세요. 문서별 동기화·권한
오류는 적용한 ACL과 서버 로그를 확인합니다.

### 스냅샷 보관과 이전

방 ID는 유니코드 문자 또는 숫자로 시작하고 문자·숫자·결합 부호·`.`·`_`·`-`만
사용하며 UTF-8 256바이트 이하여야 합니다. 대소문자를 구분합니다. WebSocket 메시지는
8 MiB, 파일 스냅샷은 4 MiB로 제한합니다.
참조 서버에는 소켓 128개, 방마다 연결 32개, 활성·로딩 중인 방 합계 128개의
상한도 있습니다. 서비스의 사용자별 할당량이나 관리자 정책을 대신하지 않습니다.

디렉터리는 sync 프로세스 하나만 소유해야 합니다. 스냅샷을 디바운스해 저장하고 정상
종료 때 남은 저장을 마칩니다. `synced`는 파일에 저장됐다는 뜻이 아닙니다.
이전 설치는 쓰기를 멈추고 백업한 뒤, 알려진 방 ID마다
`encodeURIComponent(docId) + '.ydoc'`를 `v2-<원래 방 ID의 UTF-8 SHA-256 hex>.ydoc`로
복사하세요. 구형 파일명은 자동으로 읽지 않습니다. 이미 충돌했던 파일은 백업에서 각 방의
데이터를 먼저 복원하세요. 여러 sync 프로세스를 운영하려면 이 파일 저장소를 공유하지
말고 분산 동기화와 동시 쓰기를 지원하는 저장소로 바꾸세요.

### 서버에서 시드 넣기

HTML 시드는 DOM이 필요해 브라우저에서만 파싱됩니다. 서버에서 문서를 미리 채우려면
동일한 스키마·필드로 `createSeedUpdate(schema, json)`를 한 번만 적용하세요.
이전 버전과 새 버전의 클라이언트가 빈 방에서 함께 시드하지 않도록 하세요.

## 오프라인 저장 직접 다루기

`offline: { accountId, deploymentId }`는 IndexedDB 캐시를 켭니다. 인증된 계정의 안정적인
식별자를 `accountId`에, 배포 또는 테넌트의 고유 식별자를 `deploymentId`에 전달하세요.
둘 다 비밀이 아니어야 하며 토큰을 키로 쓰지 마세요. IndexedDB는 권한 검사·암호화를
대신하지 않습니다. 로그아웃이나 계정 전환 시 기존 세션을 언마운트하고 캐시를 지우세요.
직접 만든 `Y.Doc`를 계정·배포·문서 사이에서 재사용하지 마세요.

```ts
import { persistDocToIndexedDB, clearCollabCache } from '@inkio/collab';
const scope = { accountId, deploymentId };
const persistence = persistDocToIndexedDB(docId, doc, scope);
// 로그아웃할 때 먼저 연결을 닫고 필요하면 이 캐시를 지웁니다.
await persistence.destroy();
await clearCollabCache(docId, scope);
```

> 같은 `Y.Doc`에 동일한 캐시를 두 번 연결하지 마세요. 일회성 읽기는
> `loadIndexedDBState(docId, doc, scope)`를 사용합니다. 이전의 방 ID 전용 캐시는 읽지
> 않습니다. 업그레이드 전에 기존 계정과 서버에서 미동기화 변경을 먼저 동기화하고,
> 이후 오래된 로컬 캐시를 삭제하세요. 계정을 추측해서 과거 캐시를 복사하지 마세요.

## Presence

awareness 상태는 `{ user: { name, color } }`를 싣습니다. 이름은 검증된 계정 정보가 아닌
화면 표시용이며 색상은 3자리 또는 6자리 hex를 사용합니다. `CollabPresence`가 아바타를
그리고, `useCollabPeers(provider)`로 목록을 직접 받을 수도 있습니다.
