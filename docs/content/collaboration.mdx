# 실시간 협업

`@inkio/collab`은 Yjs와 [Hocuspocus](https://tiptap.dev/docs/hocuspocus/introduction)로 여러 사용자의 편집을 동기화합니다.
처음 연결한다면 [두 탭에서 따라 하는 Yjs 레시피](/recipes/yjs-collaboration/)부터 시작하세요.

## 설치

```bash
pnpm add @inkio/collab @inkio/core yjs
```

## 클라이언트 API

`useInkioCollaborativeEditor({ docId, url, token })`은 `{ editor, provider, status, readOnly }`를 반환합니다.

| 항목 | 사용법 |
| --- | --- |
| `docId`, `url` | 방 ID와 WebSocket 주소입니다. `url` 대신 `websocketProvider`를 넘겨도 됩니다. |
| `token` | 문자열 또는 동기·비동기 함수입니다. 인증할 때마다 다시 읽습니다. |
| `editor`, `provider` | 처음에는 둘 다 `null`입니다. 준비되면 `editor`는 `EditorContent`에, `provider`는 `CollabPresence`에 전달합니다. 두 컴포넌트는 `@inkio/collab`에서 가져옵니다. |
| `status`, `readOnly` | `connecting`, `synced`, `disconnected`, `unauthorized` 중 하나입니다. `unauthorized`이면 `editor`는 `null`입니다. `readOnly`는 서버가 보기 권한을 부여했는지만 나타냅니다. 쓰기 권한으로 처음 동기화되기 전이나 `editable: false`일 때도 편집할 수 없습니다. |

- Next.js에서는 클라이언트 컴포넌트에 두세요. 기본 스타일은 `@inkio/core/style.css`와 `.inkio` 래퍼를 사용합니다.
- 일시적인 인증 실패는 해당 방만 재시도합니다. 명시적으로 거부된 토큰을 교체하거나, 토큰 함수를 갱신한 뒤 `retryCollabAuthentication(provider)`를 호출하세요.
- `extensions`를 생략하거나 `[]`를 넘기면 core 기본 확장을 유지합니다. 배열은 이름으로 확장을 추가·교체하고, `{ items, replace: true }`는 기본 목록을 직접 구성한 스키마로 대체합니다. 훅은 어느 경우든 충돌하는 실행 취소 확장을 제거하고 Yjs 협업 확장을 붙입니다.
- `onChange(editor)`는 로컬·원격 문서 변경을 알립니다. 텍스트만 필요하면 `editor.text`를 읽으세요. JSON 스냅샷을 받으려면 `onUpdate(json)`을 사용합니다.

세션 수명과 저수준 함수는 [v0.2.0 패키지 레퍼런스](https://github.com/rascalab/inkio/blob/v0.2.0/packages/collab/README.md#use)를 참고하세요.

## 여러 문서를 한 소켓으로

같은 Hocuspocus v4 서버의 여러 방은 `@inkio/collab`의 `HocuspocusProviderWebsocket`을 `new HocuspocusProviderWebsocket({ url })`로 만들어 각 훅에 `websocketProvider`로 넘기세요. 권한은 방마다 확인합니다. 마지막 방을 닫은 뒤에는 소켓을 만든 쪽에서 `destroy()`를 호출하고, 서버가 다르면 소켓을 분리하세요.

## 서버

`examples/collab-server`는 **로컬 참조 서버**이며 npm에 배포하지 않습니다. 기본 Nest 모드는 `ws://127.0.0.1:3123/collab`, 단독·분리 모드는 `ws://127.0.0.1:3123`입니다. 운영 시에는 Pages와 별도로 Node.js 서버를 운영하고 `wss://`로 연결하세요.

### NestJS에 임베드

`InkioCollabModule.forRoot({ dataDir, verify, allowedOrigins })`로 기존 Nest 서버에 붙일 수 있습니다. 기본 경로는 `/collab`입니다. `openDirectConnection`을 쓴다면 소켓 인증을 거치지 않으므로 호출 전에 문서 권한을 직접 검사하세요.

[Nest·단독 서버 설정 예제](https://github.com/rascalab/inkio/blob/v0.2.0/examples/collab-server/README.md#embedded-nest-server)

### 문서별 권한과 분리 운영

- `verify(token, docId, request)`는 인증된 사용자의 테넌트·문서 멤버십을 확인해야 합니다. 반환값은 `'write'`(편집), `'read'`(보기), `false`(거부)입니다. 장애에는 예외를 던지고, 권한이 바뀐 사용자는 재인증하도록 기존 연결을 닫으세요.
- 짧은 수명의 문서 토큰을 발급하고, 프록시에서 WebSocket 업그레이드를 허용하세요. `allowedOrigins` 또는 `COLLAB_ALLOWED_ORIGINS`는 실제 앱 Origin으로 제한합니다. Origin 검사는 문서 인증을 대신하지 않습니다.
- API와 동기화 서버를 분리하면 `COLLAB_VERIFY_KEY`는 서버 사이에서만 사용합니다. [검증 API 계약과 배포 설정](https://github.com/rascalab/inkio/blob/v0.2.0/examples/collab-server/README.md#private-verifier--sync-server)을 참고하세요.

로컬에서는 서버 시작 전에 `COLLAB_VIEWER_TOKEN`을 설정해 보세요. 새 탭에서 그 토큰을 쓰면 `synced (읽기 전용)`, 틀린 토큰을 쓰면 `unauthorized`가 표시됩니다.

앱 로그인으로 시작하려면 [React Router 인증 예제](/recipes/react-router/#로그인으로-협업-연결하기)에서
세션 쿠키로 WebSocket을 인증하고 서버에서 편집·보기 권한을 나누는 흐름을 따라 하세요.

### 스냅샷 보관과 이전

`synced`는 디스크 저장 완료가 아닙니다. 복원을 확인하려면 서버를 정상 종료하고 같은 `DATA_DIR`로 다시 시작한 뒤, 오프라인 캐시를 켜지 않은 새 탭에서 보기 토큰으로 같은 방을 여세요.

저장 디렉터리는 sync 프로세스 하나만 소유해야 합니다. [스냅샷 한도·파일 이전·복원 검사](https://github.com/rascalab/inkio/blob/v0.2.0/examples/collab-server/README.md#persistence-and-upgrades)를 참고하세요.

### 서버에서 시드 넣기

`content`는 쓰기 권한으로 동기화된 빈 문서만 초기화합니다. 클라이언트의 스키마·필드·시드가 같아야 하며, 다른 시드가 동시에 들어가면 둘 다 남을 수 있습니다. 클라이언트 버전이 섞이면 서버에서 `createSeedUpdate(schema, json)`으로 한 번만 초기화하세요.

## 오프라인 저장 직접 다루기

`offline: { accountId, deploymentId }`를 넘기면 IndexedDB 캐시가 켜집니다. 토큰이 아닌 안정적인 식별자를 사용하세요. 쓰기가 허용됐던 세션은 연결이 끊겨도 편집할 수 있지만, 새 오프라인 세션은 권한이 확인될 때까지 읽기 전용입니다.

로그아웃·계정 전환 시 기존 세션을 종료한 뒤 캐시를 비우세요. 캐시는 권한 검사나 암호화를 대신하지 않습니다. [캐시 삭제·이전 방법](https://github.com/rascalab/inkio/blob/v0.2.0/packages/collab/README.md#use)

완전히 오프라인인 상태에서 앱 페이지도 다시 열려면
[Vite 앱 셸 캐시](/recipes/react-router/#오프라인에서-협업-앱-다시-열기)를 따로 켜세요.

## Presence

`CollabPresence`는 다른 접속자의 아바타를 표시하고, `useCollabPeers(provider)`는 자신을 제외한 목록을 반환합니다. 표시 이름은 계정 신원이 아니며, 접속 상태는 문서에 저장되지 않습니다.
