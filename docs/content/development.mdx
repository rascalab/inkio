# 개발 가이드

## 패키지 구조

```text
packages/
  core/         # low-level foundation
  advanced/     # notion-like and integration-heavy extensions
  simple/       # classic WYSIWYG entry point
  editor/       # notion-like entry point
  image-editor/ # optional image editing UI
  collab/       # Yjs-based realtime collaboration client
```

## 역할 분리

- `@inkio/core`
  - primitives, menus, icons, markdown, `ImageBlock`, callout, details/toggle, table, keyboard shortcuts
- `@inkio/advanced`
  - slash command, block handle, mention, hashtag, wiki link, bookmark, comment
- `@inkio/simple`
  - core-only classic editor
- `@inkio/editor`
  - advanced를 포함한 notion-like editor
- `@inkio/collab`
  - Yjs 실시간 협업 클라이언트 (서버 미포함, 와이어 프로토콜 + transport)

## 공통 chrome contract

배치 구조는 패키지마다 유지합니다.

- `simple`: classic toolbar-first
- `editor`: notion-like
- `image-editor`: fullscreen overlay

대신 시각 시스템은 공통 surface 토큰을 기준으로 맞춥니다.

- `surface-shell`
  - toolbar, dock, command bar, sidebar
- `surface-panel`
  - popover, bubble menu, floating card, picker
- `surface-field`
  - input, select, textarea, search, segmented control

focus ring, border, blur, shadow, field styling은 가능한 한 이 공용 contract를 따릅니다.

## dependency 정책

- `react`, `react-dom`만 peer
- Inkio가 직접 쓰는 Tiptap runtime은 각 패키지 `dependencies`
- `@inkio/core`는 published package지만 일반 사용자에게 직접 시작점으로 안내하지 않습니다

## 릴리스

루트, 6개 패키지, docs는 모두 같은 버전을 씁니다.

```bash
pnpm release:version 0.0.8   # 루트·패키지·docs의 version을 한 번에 변경
# CHANGELOG.md에 ## [0.0.8] 항목을 추가하고 main에 커밋·푸시
git tag v0.0.8
git push origin v0.0.8
```

태그를 푸시하면 `Publish Packages` 워크플로가 다음 순서로 실행됩니다.

1. 태그 버전과 모든 `package.json`의 버전이 같은지 확인
2. 태그 커밋이 main에 있고 그 커밋의 CI가 성공했는지 확인 (CI가 진행 중이면 대기)
3. 패키지 빌드, publint/attw/budgets, release smoke
4. npm trusted publishing(OIDC)으로 provenance를 붙여 배포 (npm 토큰 불필요)
5. 배포가 성공하면 `Deploy Docs`가 같은 커밋으로 문서 사이트를 배포

main에 푸시하는 것만으로는 문서 사이트가 바뀌지 않습니다. 릴리스 없이 문서만 고쳐 내보내야 하면 Actions에서 `Deploy Docs`를 수동 실행합니다.
