# 댓글 서버 연동

문서의 `comment` 마크에는 `commentId`와 `resolved` 속성이 저장됩니다. 메시지와 작성자는
마크에 들어가지 않습니다. 앱의 서버가 스레드 데이터와 해결 상태를 저장하고 권한을 확인합니다.
inkio는 댓글 작성기·패널·팝오버를 제공하지만 아래 HTTP API는 제공하지 않습니다.

읽기 전용(`editable={false}`) 에디터에서는 댓글 작성·답글·해결·삭제가 모두
비활성화됩니다. 스레드 조회(popover 표시)는 동작합니다.

## 서버 계약

다음은 앱이 구현할 API 예시입니다. 조회와 작성은 문서 ID로 범위를 한정합니다.

| 연산 | 예시 엔드포인트 | 설명 |
|------|----------------|------|
| 스레드 조회 | `GET /api/comments?documentId=...` | 해당 문서의 스레드 목록 반환 (날짜는 ISO 문자열) |
| 작성 | `POST /api/comments` `{ documentId, commentId, text, selection }` | 첫 메시지 스레드 생성 |
| 답글 | `POST /api/comments/:id/replies` `{ text }` | 메시지 추가 |
| 해결/삭제 | `PATCH /api/comments/:id` `{ resolved }`, `DELETE /api/comments/:id` | 상태 변경. 삭제 성공은 `204 No Content` |

문서의 `commentId`는 권한을 증명하지 않습니다. 조회·작성·답글·수정·삭제마다 인증된 사용자에게
해당 문서와 스레드의 접근 권한이 있는지 서버에서 확인하세요. `getComments`도 현재 문서에 대해
서버가 확인해 준 스레드만 반환해야 합니다. 현재 문서에 알려진 스레드가 아니면 기존 스레드
변경 콜백을 연결한 UI에서도 그 동작을 제공하지 않습니다.

```ts
// 서버가 들고 있을 행 모양 (ORM은 자유)
interface CommentRow {
  id: string;          // commentId
  documentId: string;  // 어떤 문서의 댓글인지
  resolved: boolean;
  messages: Array<{ id: string; author: string; text: string; createdAt: string }>;
}
```

## 클라이언트 연동

```tsx
import { useCallback, useEffect, useState } from 'react';
import { Editor, type CommentData } from '@inkio/editor';

type ThreadJson = Omit<CommentData, 'messages'> & {
  messages: Array<Omit<CommentData['messages'][number], 'createdAt'> & { createdAt: string }>;
};

function toThread(row: ThreadJson): CommentData {
  return { ...row, messages: row.messages.map(m => ({ ...m, createdAt: new Date(m.createdAt) })) };
}

async function api<T>(url: string, init?: RequestInit): Promise<T> {
  const res = await fetch(url, {
    ...init,
    headers: { 'content-type': 'application/json', ...init?.headers },
  });
  if (!res.ok) throw new Error(`comments API failed: ${res.status}`);
  return (res.status === 204 ? undefined : await res.json()) as T;
}

export function DocumentPage({ documentId }: { documentId: string }) {
  // 스레드 캐시: getComments는 동기 함수라서 캐시에서 읽습니다.
  const [threads, setThreads] = useState<Map<string, CommentData>>(new Map());
  const upsert = useCallback((row: ThreadJson) => {
    const data = toThread(row);
    setThreads((prev) => new Map(prev).set(data.id, data));
  }, []);

  // 문서 전환 시 상위에서 <DocumentPage key={documentId} ... />로 다시 마운트합니다.
  useEffect(() => {
    api<ThreadJson[]>(`/api/comments?documentId=${encodeURIComponent(documentId)}`).then((rows) => {
      setThreads(new Map(rows.map(r => [r.id, toThread(r)])));
    });
  }, [documentId]);

  return (
    <Editor
      content="<p>...</p>"
      comment={{
        getComments: (commentId) => threads.get(commentId) ?? null,
        onSubmit: async (commentId, text, selection) => {
          const row = await api<ThreadJson>('/api/comments', {
            method: 'POST',
            body: JSON.stringify({ documentId, commentId, text, selection }),
          });
          upsert(row);
        },
        onReply: async (commentId, text) => {
          const row = await api<ThreadJson>(`/api/comments/${encodeURIComponent(commentId)}/replies`, {
            method: 'POST',
            body: JSON.stringify({ text }),
          });
          upsert(row);
        },
        onResolve: async (commentId) => {
          const row = await api<ThreadJson>(`/api/comments/${encodeURIComponent(commentId)}`, {
            method: 'PATCH',
            body: JSON.stringify({ resolved: true }),
          });
          upsert(row);
        },
        onDelete: async (commentId) => {
          await api<void>(`/api/comments/${encodeURIComponent(commentId)}`, { method: 'DELETE' });
          setThreads((prev) => {
            const next = new Map(prev);
            next.delete(commentId);
            return next;
          });
        },
      }}
    />
  );
}
```

## 동작 흐름

1. 사용자가 텍스트를 선택하고 댓글을 달면 에디터가 `commentId`를 생성해
   문서에 마크로 저장하고 `onSubmit`을 호출합니다.
2. 마크 클릭 시 팝오버가 `getComments(commentId)`로 캐시에서 스레드를 읽어 보여줍니다.
3. 답글·해결·삭제 콜백에서 서버 저장 후 스레드 캐시를 갱신합니다. 해결·삭제 시
   에디터의 마크는 콜백이 완료되기 전에 바뀔 수 있습니다.
   위 예제에서는 캐시 변경 시 `getComments` 함수도 새로 전달되어 열린 팝오버가 다시 조회합니다.
   `CommentPanel`도 `threads`가 바뀌면 갱신을 알립니다. 함수와 패널 props가 그대로인 외부
   캐시(예: ref)나 직접 조합한 확장에서는 갱신 후 `@inkio/advanced`의 `notifyCommentThreadsChanged()`를 호출하세요.
4. `<CommentPanel editor={editor} threads={[...threads.values()]} />`은 `Editor`에 등록한
   답글·해결·삭제 콜백을 사용합니다. 패널에서만 삭제를 숨기려면 `onDelete={false}`를
   넘기세요. 함수를 넘기면 해당 패널에서는 등록한 콜백 **대신** 그 함수만 호출됩니다.

`comment` prop과 `getDefaultExtensions({ comment })`는 `CommentConfig`의 `onSubmit`·`getComments`
이름을 사용합니다. `@inkio/advanced`의 `Comment` 확장을 직접 구성하는 경우에만
`Comment.configure(toCommentOptions(comment))`로 변환하거나 저수준 `CommentOptions`의
`onCommentSubmit`·`getThread`를 사용하세요. `CommentPanel`의 `currentUser`는 표시 이름이지
인증 정보나 프리셋 `comment` 옵션이 아닙니다.

## Viewer

읽기 전용 화면도 같은 캐시를 씁니다. 댓글 기능이 필요 없으면
`comment` prop을 생략하세요 (기본 꺼짐).

Viewer의 내장 팝오버는 조회 전용이며 `getComments`만 받습니다.

```tsx
<Viewer
  content={content}
  comment={{
    getComments: (commentId) => threads.get(commentId) ?? null,
  }}
/>
```

## 주의사항

- `getComments`는 동기 함수입니다. 비동기 fetch를 직접 넣지 말고 위처럼
  캐시를 먼저 채워 두세요.
- 네트워크 오류를 앱에서 처리하세요. inkio는 댓글 콜백의 Promise를 기다리거나,
  저장 실패 시 문서 마크를 되돌리지 않습니다. 실패하면 오류를 보여 주고 재시도
  또는 저장된 문서와 캐시를 기준으로 복구할 수 있게 하세요.
- 패널이나 팝오버로 삭제하면 해당 ID의 문서 마크도 제거됩니다. 서버에서 직접
  삭제할 때는 문서에 남은 마크를 별도로 정리하세요.
- 패널은 문서에 마크가 있는 스레드만 보여 줍니다. 댓글을 단 글을 지우면 패널에서
  사라지고, 실행 취소로 글이 돌아오면 다시 나타납니다. 이때 `onDelete`는 호출되지
  않으므로 저장소의 스레드 데이터는 그대로 남습니다. 저장된 JSON의 참조 목록은
  `read(json).commentIds`, 편집 중인 문서의 목록은 `editor.commentIds`로 읽습니다.
  이 목록은 삭제 권한을 증명하지 않습니다. 서버에서 저장된 문서 버전과 권한을 확인하고
  실행 취소·협업 편집으로 참조가 돌아올 수 있음을 고려해 보관 기간을 정하세요.
