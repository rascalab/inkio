# React Router Recipe

`examples/react-router`는 Vite, [React Router v7의 선언형 라우팅](https://reactrouter.com/start/declarative/routing), `@inkio/simple`을 사용합니다.

`v0.1.0` 저장소 루트에서 실행하세요.

```bash
pnpm install
pnpm --filter example-react-router dev
```

`src/main.tsx`는 `BrowserRouter`로 앱을 감싸고 `@inkio/simple/style.css`를 앱
스타일보다 먼저 가져옵니다. 개발 서버는 워크스페이스 패키지 소스를 사용합니다.

`/documents/:documentId`에서 편집하고, `/documents/:documentId/read`에서 읽습니다.
편집 화면은 하단 고정 툴바를 사용합니다. 읽기 화면은 같은 프리셋을
`editable={false}`로 렌더링하고 툴바를 숨깁니다. 존재하지 않는 문서에는
찾을 수 없다는 화면이 표시됩니다.

문서 ID나 편집 모드가 바뀔 때 `key`로 인스턴스를 교체합니다. Inkio의 `content`는
초기값이므로, 같은 인스턴스에 다른 문서의 `content`만 전달하지 않습니다.

편집본은 라우트 상위의 메모리에만 저장합니다. 링크로 이동하거나 브라우저의 뒤로
가기를 눌러도 앱이 마운트되어 있으면 초안이 남지만, 새로고침하면 초기화됩니다.

## 정적 배포

```bash
pnpm build:packages
pnpm --filter example-react-router build
pnpm --filter example-react-router preview
```

기본 `build`는 워크스페이스 소스 대신 패키지 배포 파일을 사용합니다.
`preview`는 로컬 확인용입니다. `examples/react-router/dist`를 정적 호스트에 올리고
`/documents/*`, `/collab`, `/collab/auth`를 직접 열거나 새로고침할 수 있도록 SPA rewrite를 설정하세요. `/api/collab-auth/`는 rewrite하지 말고 인증 서버로 프록시하세요(WebSocket 업그레이드 포함).
하위 경로에 배포하면 `BrowserRouter`는 Vite의 `base`를 사용합니다.

## 오프라인에서 협업 앱 다시 열기

일반 빌드에는 서비스 워커를 넣지 않습니다. Vite 8 앱에서 필요한 경로만 지정하세요.

```ts
import { defineConfig } from 'vite';
import { inkioOffline } from '@inkio/collab/vite';

export default defineConfig({
  plugins: [inkioOffline({ routes: ['/collab', '/collab/auth'] })],
});
```

`routes`에는 Vite `base`를 뺀 앱 경로를 지정합니다. 워커는 정적 `index.html`과 빌드된
JS·CSS만 캐시합니다. 인증·API 응답, 사용자별 HTML에는 쓰지 마세요. 앱에 이미 서비스
워커가 있다면 새 워커 대신 기존 워커의 캐시 정책에 이 경로를 추가하세요.

저장소의 예제에서는 아래처럼 켤 수 있습니다.

```bash
pnpm build:packages
pnpm --filter example-react-router build:offline
pnpm --filter example-react-router preview --host 127.0.0.1 --port 5183 --strictPort
```

[로컬 협업 서버](/recipes/yjs-collaboration/#1-로컬-서버-시작하기)를 켤 때
`COLLAB_ALLOWED_ORIGINS=http://127.0.0.1:5183`을 지정하세요. 같은 주소의 `/collab`을
온라인에서 먼저 열어 `Synced`와 `App ready to reopen offline.`을 확인한 뒤, 네트워크를
끊고 새로고침합니다. 토큰을 다시 입력하면 IndexedDB에 저장된 문서를 볼 수 있습니다.

오프라인으로 새로 연 세션은 쓰기 권한을 다시 확인할 때까지 읽기 전용입니다.
한 번도 열지 않았거나 브라우저에서 캐시를 지운 앱은 오프라인에서 시작할 수 없습니다.
예제는 한 명의 로컬 테스트 계정을 가정합니다. 실제 앱은 문서 캐시를 인증된 계정과
배포별로 나누고 로그아웃 시 정리하세요. 테스트 토큰을 빌드에 넣지 마세요.

## 로그인으로 협업 연결하기

`/collab/auth`는 문서 토큰을 붙여 넣는 대신 앱에 로그인하는 예제입니다. 로컬에서
`editor`는 편집, `viewer`는 보기 권한을 갖습니다.

첫 번째 터미널에서 인증 서버를 실행하세요.

```bash
pnpm --filter example-collab-server build
export DATA_DIR="$(mktemp -d)"
export COLLAB_AUTH_ORIGIN=http://127.0.0.1:5183
export COLLAB_AUTH_EDITOR_PASSWORD="$(openssl rand -hex 24)"
export COLLAB_AUTH_VIEWER_PASSWORD="$(openssl rand -hex 24)"
printf 'editor: %s\nviewer: %s\n' "$COLLAB_AUTH_EDITOR_PASSWORD" "$COLLAB_AUTH_VIEWER_PASSWORD"
COLLAB_HOST=127.0.0.1 PORT=3124 pnpm --filter example-collab-server start:auth
```

두 번째 터미널에서는 위의 `build:offline`과 `preview` 명령을 실행한 뒤
`http://127.0.0.1:5183/collab/auth`를 여세요. 첫 터미널에서 만든 비밀번호로 로그인합니다.
두 계정을 비교하려면 일반 창과 시크릿 창을 사용하세요. 같은 브라우저 프로필의 탭은 로그인
쿠키를 공유합니다.

- 앱 서버가 HttpOnly 세션 쿠키를 발급합니다. HTTP와 WebSocket 모두 같은 세션을 사용하고,
  편집·보기 권한은 서버가 문서별로 검사합니다.
- 서비스 워커는 앱 화면만 캐시합니다. 이미 쓰기 권한으로 동기화한 세션은 연결이 끊겨도 편집할 수 있고, 보기 계정은 계속 읽기 전용입니다. 오프라인에서 새로 열면 세션을 확인할 때까지 문서를 표시하지 않습니다.
- 로그아웃은 서버에서 세션을 폐기하고, 브라우저에서 해당 계정의 문서 캐시를 지웁니다.

루프백 데모입니다. 운영에서는 앱의 기존 로그인·세션 저장소와 문서 ACL을 사용하고,
HTTPS/WSS에서 앱과 인증·WebSocket 엔드포인트를 같은 출처로 제공하세요.
