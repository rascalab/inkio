# Yjs 실시간 협업 레시피

Inkio v0.0.9의 Hocuspocus 참조 서버에 React 에디터를 연결합니다. 같은 방을 두 탭에서
열어 변경이 오가는지, 보기 권한과 접근 거부가 구분되는지, 서버를 다시 시작해도 내용이
남아 있는지 확인합니다. Node.js 22.12 이상, pnpm 12.10.0, Git, OpenSSL이 필요합니다.

## 1. 로컬 서버 시작하기

첫 번째 터미널에서 `v0.0.9` 태그를 체크아웃하고 Nest 참조 서버를 실행합니다.
아래 설정은 루프백 주소에서 `shared-doc` 한 방만 열고, 편집·보기 토큰을 각각 생성합니다.

```bash
git clone --branch v0.0.9 --depth 1 https://github.com/rascalab/inkio.git inkio-v0.0.9
cd inkio-v0.0.9
pnpm install --frozen-lockfile
pnpm --filter example-collab-server build

export DATA_DIR="$(mktemp -d)"
export COLLAB_HOST=127.0.0.1
export PORT=3123
export COLLAB_ROOM_ID=shared-doc
export COLLAB_ALLOWED_ORIGINS=http://127.0.0.1:5173
export COLLAB_EDITOR_TOKEN="$(openssl rand -hex 32)"
export COLLAB_VIEWER_TOKEN="$(openssl rand -hex 32)"
printf 'Editor token: %s\nViewer token: %s\n' "$COLLAB_EDITOR_TOKEN" "$COLLAB_VIEWER_TOKEN"
pnpm --filter example-collab-server start
```

서버가 `ws://127.0.0.1:3123/collab`에서 대기합니다. 터미널은 재시작 검증까지 유지하세요.
출력한 토큰은 로컬 실습 전용입니다. React 코드, `VITE_*` 환경 변수, URL 또는 저장소에
넣지 말고 아래 입력란에만 붙여 넣으세요.

## 2. React 클라이언트 만들기

두 번째 터미널에서 Inkio 체크아웃 **밖에** [Vite React 앱](https://vite.dev/guide/#scaffolding-your-first-vite-project)을
만듭니다. React와 React DOM은 템플릿이 설치하는 의존성을 사용합니다.

```bash
pnpm create vite@latest inkio-yjs-client --template react --no-interactive
cd inkio-yjs-client
pnpm add @inkio/collab@0.0.9 @inkio/core@0.0.9 yjs@^13.6.13
```

`src/main.jsx`의 내용을 아래 코드로 교체합니다. `EditorContent`도 `@inkio/collab`에서
가져오므로 `@tiptap/react`를 별도로 설치하지 않습니다. 기본 본문 스타일은 core의 CSS와
`.inkio` 래퍼로 적용합니다.

```jsx
import { useState } from 'react';
import { createRoot } from 'react-dom/client';
import { CollabPresence, EditorContent, useInkioCollaborativeEditor } from '@inkio/collab';
import '@inkio/core/style.css';

function Room({ name, token }) {
  const { editor, provider, status, readOnly } = useInkioCollaborativeEditor({
    docId: 'shared-doc',
    url: 'ws://127.0.0.1:3123/collab',
    token,
    user: { name, color: '#2563eb' },
    content: '<p>공유 문서를 편집해 보세요.</p>',
    ariaLabel: '공유 문서',
  });

  return (
    <>
      <p role="status">{status}{readOnly ? ' (readOnly)' : ''}</p>
      <CollabPresence provider={provider} />
      {editor && (
        <div className="inkio inkio-editor inkio-container-default">
          <EditorContent editor={editor} />
        </div>
      )}
    </>
  );
}

function App() {
  const [session, setSession] = useState(null);

  function join(event) {
    event.preventDefault();
    const data = new FormData(event.currentTarget);
    setSession({ name: data.get('name'), token: data.get('token') });
  }

  return (
    <main>
      <h1>공유 문서</h1>
      {session ? (
        <>
          <button type="button" onClick={() => setSession(null)}>연결 끊기</button>
          <Room {...session} />
        </>
      ) : (
        <form onSubmit={join} autoComplete="off">
          <p><label>표시 이름 <input name="name" required /></label></p>
          <p><label>문서 토큰 <input name="token" type="password" required /></label></p>
          <button type="submit">연결</button>
        </form>
      )}
    </main>
  );
}

createRoot(document.getElementById('root')).render(<App />);
```

토큰은 현재 탭의 메모리에만 두고, 연결을 끊으면 협업 세션과 함께 정리합니다. 서버의
Origin 허용 목록과 일치하도록 `localhost`가 아닌 `http://127.0.0.1:5173`을 여세요.

```bash
pnpm dev --host 127.0.0.1 --port 5173 --strictPort
```

## 3. 두 탭에서 동기화와 권한 확인하기

1. 두 탭에서 `http://127.0.0.1:5173`을 엽니다. 표시 이름을 각각 `Ada`, `Lin`으로
   입력하고 두 탭 모두 **Editor token**으로 연결합니다. 두 탭이 `synced`가 되면
   한쪽에서 문장을 추가하고 다른 쪽에 바로 표시되는지 확인합니다. 반대쪽에서도 편집해 보세요.
2. 두 번째 탭에서 **연결 끊기**를 누른 뒤 **Viewer token**으로 다시 연결합니다.
   `synced (readOnly)`이고 내용을 읽을 수 있지만 입력해도 문서는 바뀌지 않습니다.
   첫 번째 탭에서 편집하면 두 번째 탭에는 계속 변경이 반영됩니다.
3. 두 번째 탭의 연결을 끊고 문서 토큰에 `wrong-token`을 입력해 연결합니다.
   `unauthorized`가 표시되고 에디터나 문서 내용이 나타나지 않아야 합니다.

## 4. 서버 재시작 후 복원 확인하기

1. 첫 번째 탭에서 기억하기 쉬운 문장(예: `서버 재시작 뒤에도 남는 문장`)을 추가합니다.
   두 번째 탭에 보기 토큰으로 다시 연결해 그 문장이 도착했는지 확인합니다.
2. 첫 번째 터미널에서 `Ctrl+C`로 서버를 정상 종료하고 프롬프트가 돌아올 때까지
   기다립니다. `synced`는 동기화 상태이지 디스크 저장 완료가 아닙니다. 정상 종료 시
   서버가 대기 중인 저장을 마칩니다. 서버가 다시 시작되기 전에 두 탭을 모두 닫습니다.
3. 같은 터미널에서 아래 명령을 실행합니다. 방 ID, 토큰, `DATA_DIR`를 새로 만들지 않습니다.

   ```bash
   ls "$DATA_DIR"/v2-*.ydoc
   pnpm --filter example-collab-server start
   ```

4. 새 탭을 열어 **Viewer token**으로 연결합니다. 읽기 전용인데도 저장한 문장이 보이면
   서버 스냅샷에서 복원된 것입니다. 이 클라이언트는 IndexedDB 캐시를 사용하지 않으며
   읽기 전용 세션은 초기 `content`를 삽입하지 않습니다.

서버 모드별 권한, 변경 전달, 재시작 복원을 자동으로 확인하려면 태그 체크아웃에서
`pnpm --filter example-collab-server smoke`를 실행할 수 있습니다.

## 운영에 연결하기

- 참조 CLI의 고정 방 토큰 대신 앱에서 인증된 사용자에게 발급한 짧은 수명의 문서 토큰을
  사용하세요. 접속할 때마다 `verify(token, docId, request)`에서 사용자와 해당 테넌트·문서
  멤버십을 확인해 `'write'`, `'read'`, `false`를 반환합니다. `'read'`는 서버에서도 쓰기를
  거부합니다. 권한이 바뀌면 기존 연결을 닫아 다시 인증하도록 하세요. 표시 이름이나
  클라이언트에서 전달한 `docId`만으로 권한을 주면 안 됩니다.
- 브라우저는 HTTPS 앱에서 `wss://`로 공개 동기화 서버에 연결합니다. 예를 들어 Nest 임베드
  모드의 기본 경로는 `wss://sync.example.com/collab`이고 단독·분리 모드의 기본 경로는
  `wss://sync.example.com`입니다. 프록시가 WebSocket 업그레이드를 전달하도록 하고,
  `COLLAB_ALLOWED_ORIGINS`(임베드 시 `allowedOrigins`)와 프록시에서 `https://app.example.com`
  같은 실제 앱 Origin을 제한하세요. Origin은 ACL을 대신하지 않습니다.
  배포 환경에서 요청·연결 빈도와 사용자별 문서 수도 제한하세요.
- 분리 모드의 `COLLAB_VERIFY_KEY`는 브라우저에 전달하는 문서 토큰과 다른 서버 간 비밀입니다.
  sync 서비스만 이 키를 Bearer 헤더로 보내며, 검증 API는 비공개 네트워크에 두고 호스트 간
  통신은 HTTPS를 사용하세요. 키나 비공개 검증 URL을 프런트엔드에 넣지 마세요.

[실시간 협업 레퍼런스](/collaboration/)에서 클라이언트 API, 분리 서버의 요청·응답 계약,
스냅샷 보관과 용량 제한을 확인하세요. 서버 읽기 전용 동작은
[Hocuspocus 인증 훅](https://tiptap.dev/docs/hocuspocus/server/hooks#on-authenticate)을 따릅니다.
