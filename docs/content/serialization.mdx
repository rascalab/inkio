# 직렬화

## 에디터 인스턴스에서 읽기

`Editor`의 `onCreate`와 `onChange`는 현재 에디터 인스턴스를 넘겨줍니다. `getJSON()` 없이 문서 값을 읽을 수 있습니다. 인스턴스를 보관할 때는 원본 `TiptapEditor` 대신 프리셋의 `InkioEditor` 타입을 쓰세요.

```ts
editor.text          // 일반 텍스트
editor.stats         // { words, chars, blocks }
editor.summary(80)   // 말줄임표를 포함해 최대 80자
editor.mentions      // [{ id: 'u1', label: 'Alice' }]
editor.hashTags      // ['inkio', 'editor']
editor.headings      // [{ id, level, text, index }]
editor.commentIds    // 본문이 참조하는 스레드 ID. 댓글 데이터나 접근 권한이 아님
```

`text`에는 멘션과 태그가 화면에 표시되는 `@Ada`, `#inkio` 형태로 들어갑니다. 반대로 `mentions`와 `hashTags`는 실제 노드에서만 읽으므로 직접 입력한 `@Ada`는 멘션 목록에 들어가지 않습니다. 같은 문서에서 getter를 다시 읽으면 계산 결과를 재사용합니다. 글자 수를 화면에 표시하려면 `onChange={(editor) => setCount(editor.stats.chars)}`처럼 변경 시점에 읽으세요.
`mentions`는 ID가 있는 멘션을 읽고, 라벨이 비어 있으면 ID를 라벨로 사용합니다. `hashTags`도 라벨 또는 ID에서 선행 `#`를 제거하며, 빈 태그는 제외합니다.

`summary()`의 기본 한도는 140입니다. `stats.chars`처럼 JavaScript 문자열 길이(UTF-16) 기준이며 `...`도 한도에 포함합니다.

`stats.blocks`는 문서 루트를 제외한 구조 블록 수입니다. 목록 하나에 항목·문단이 하나씩 있으면 3개이며, 이미지·북마크·목차도 각각 1개입니다. 북마크는 제목(없으면 URL)과 설명, 이미지는 캡션(없으면 대체 텍스트)을 미리보기에 포함합니다. 코드 블록에서는 들여쓰기와 빈 줄을 유지합니다.

## 인스턴스 없이 저장된 JSON 읽기

`read(json)`은 이미 메모리에 있는 `JSONContent`를 읽습니다. 파일이나 네트워크에 접근하지 않고, 에디터 없이도 같은 문서 값을 제공하는 읽기 전용 `InkioDocument`를 반환합니다. `@inkio/editor`, `@inkio/simple`, `@inkio/core`의 패키지 루트에서 가져올 수 있습니다.

```ts
import { read } from '@inkio/editor';

const doc = read({
  type: 'doc',
  content: [{
    type: 'heading',
    attrs: { level: 2 },
    content: [{ type: 'mention', attrs: { id: 'u1', label: 'Ada' } }],
  }],
});

doc.text             // '@Ada'
doc.stats.chars      // 4
doc.summary(80)      // '@Ada'
doc.mentions         // [{ id: 'u1', label: 'Ada' }]
doc.hashTags         // []
doc.headings[0].text // '@Ada'
doc.commentIds       // []
```

값은 필요할 때 계산하므로 같은 JSON에서 여러 값을 읽을 때는 `doc`을 재사용하세요. 결과는 이 객체에 캐시됩니다. 입력 JSON은 중첩 노드까지 변경하지 말고, 문서가 바뀌면 새 JSON으로 `read(nextJson)`을 호출하세요. 라이브 에디터가 있다면 `read(editor.getJSON())` 대신 `editor.text`처럼 직접 읽으면 됩니다.

커스텀 노드의 `renderText`나 블록 정의까지 반영하려면 그 문서를 만든 스키마를 `read(json, { schema })`로 전달하세요. JSON만으로는 앱에 등록된 확장의 동작을 알 수 없습니다.

## Markdown 읽고 쓰기

`Markdown`을 `extensions`에 등록하면 `onCreate`로 받는 에디터에서 바로 읽고 쓸 수 있습니다. `@inkio/simple`에서는 `@inkio/simple/markdown`에서 가져오세요.
`@inkio/core`의 `Editor`에서도 `extensions={[Markdown]}`은 기본 확장에 `Markdown`을 추가합니다. 기본 확장 목록을 다시 넘길 필요는 없습니다.

```tsx
import { Editor } from '@inkio/editor';
import { Markdown } from '@inkio/editor/markdown';

<Editor
  extensions={[Markdown]}
  onCreate={(editor) => {
    editor.markdown = '## 제목';
    console.log(editor.markdown); // '## 제목'
  }}
/>
```

`editor.markdown = source`는 현재 문서를 교체합니다. 입력 한도나 스키마 검사에서 실패하거나 편집 플러그인이 교체를 막거나 원래 내용으로 되돌리면 예외가 발생합니다. 파일 가져오기는 `try/catch`로 처리하고 실패하면 원본 파일을 보관하세요. 성공해도 플러그인이 내용을 정규화할 수 있고, 서버에 저장된 것은 아닙니다.

확장 목록을 변수로 빼면 `const extensions = [Markdown] as const`로 선언하세요. TypeScript가 플러그인 등록 여부를 알 수 있어 `onCreate`에서도 별도 타입 단언이 필요 없습니다.
확장 구성이 바뀌면 새 인스턴스를 만듭니다. 새 스키마에 맞춰 내용을 옮기므로 블록의 감싸는 구조나 허용되지 않는 서식은 달라질 수 있습니다. 선택은 남은 내용에 맞춰 복원하며, 선택했던 내용이 사라지면 같은 위치를 보장하지 않습니다. 실행 취소 기록은 이전하지 않습니다. 외부에 인스턴스를 보관한다면 새 `onCreate` 값으로 교체하세요.
예를 들어 인용문이 문단만 허용하도록 바뀌면 그 안의 이미지는 허용되는 상위 위치로 옮깁니다. 이미지 타입이 새 스키마에도 있지만 어느 위치에도 넣을 수 없다면 이미지를 조용히 빼고 계속하지 않고 이전 오류를 냅니다. 문서 구조를 제한하기 전에는 원본 JSON을 보관하세요.
React에서는 배열 자체가 아니라 등록한 확장 인스턴스를 재사용하세요. `Markdown.configure(...)` 같은 호출은 컴포넌트 밖에 두거나 `useMemo`로 감싸세요.

초기 문서만 불러온다면 `content={parseMarkdown(source)}`를 쓰세요. 에디터 없이 변환할 때는 같은 `/markdown` 진입점의 `parseMarkdown`, `stringifyMarkdown`을 사용합니다. 패키지 루트만 쓰는 화면에는 Markdown 파서가 포함되지 않습니다.

`parse`와 `stringify`를 하나의 객체로 전달하려면 `createMarkdownAdapter()`를 사용하세요. 이 함수는 인자를 받지 않으며 에디터의 확장 목록은 독립 변환 결과에 영향을 주지 않습니다.

일반 텍스트로 복사한 Markdown을 문서 구조로 붙여넣으려면 `MarkdownPaste`를 추가하세요.
HTML이 함께 복사된 경우, 코드 블록 안, 서식 없이 붙여넣기에서는 Markdown 변환을 건너뛰고 기본 붙여넣기 동작을 따릅니다.

```tsx
import { MarkdownPaste } from '@inkio/editor/markdown';

<Editor extensions={[MarkdownPaste]} />
```

Markdown은 지원하는 문서 구조만 왕복합니다. core 서식도 모두 보존되지는 않습니다. 예를 들어 글자색과 정렬은 사라지므로 원본을 그대로 보관하려면 JSON을 저장하세요.
구현은 `remark/unified` 기반이며 HTML bridge를 사용하지 않습니다.
인라인 목차 블록은 `::toc`로 저장하고, 깊이 설정이 있으면 `::toc{maxLevel="4"}`처럼 보존합니다.
`[[가이드]]`는 위키링크지만 `[[가이드]](/guide)`는 `[가이드]`를 라벨로 쓰는 일반 링크입니다. `[가이드][docs]` 같은 참조형 링크와 이미지도 정의를 찾아 가져옵니다. 알 수 없는 `:이름`이나 `:::블록` 구문은 본문에서 지우지 않고 원문 텍스트로 남깁니다.

이미지 캡션은 Markdown에서도 읽을 수 있는 강조 문단으로 내보냅니다. Inkio는 바로 옆 주석을 이용해 캡션과 이미지 크기·정렬을 복원합니다. 문장 중간의 이미지는 Inkio에서 블록이므로 앞뒤 문단과 나뉩니다. 접기 블록의 열린 상태는 `<details open>`으로 유지합니다.

지원하지 않는 이미지 URL은 텍스트로 남기고 나머지 문서를 보존합니다.
외부에서 받은 Markdown은 입력 크기를 제한하고, 가져오기가 실패하면 저장 문서로 덮어쓰지
마세요. 내보낸 Markdown을 HTML을 허용하는 다른 도구에서 표시할 때도 출력 HTML을
그 도구의 신뢰 경계에서 정화해야 합니다.

GFM 표에는 셀 병합이 없습니다. 병합한 표는 빈 칸으로 열 위치를 유지해 내보내고, 병합 정보는 표 바로 앞의 주석(`<!-- inkio:table-spans ... -->`)에 남겨 Inkio가 다시 읽을 때 복원합니다. 다른 도구에서는 병합이 풀린 표로 보입니다.

### Advanced 노드 처리

| 노드 | 내보내기 | 다시 읽기 |
|------|----------|----------|
| 멘션 | `@라벨` 텍스트 | 텍스트 유지 (이메일 오인식 방지) |
| 해시태그 | `#라벨` 텍스트 | 텍스트 유지 |
| 위키링크 | `[[이름]]` (`label` 우선, 없으면 `href`) | 허용된 이름을 `href`로 복원합니다. 서로 다른 라벨과 대상은 구분해 보존하지 않습니다. |
| 북마크 | `[제목](URL)` 링크 | 링크 (카드 복원 안 됨) |
| 댓글 | 버려짐 (마크 제거, 텍스트 유지) | — (스레드는 서버에 별도 저장) |
