# 트러블슈팅

에러 메시지별로 원인 → 해결책 순서로 정리했습니다. 개념 설명은 각 링크 문서 참고.

## Hydration mismatch

**증상**: `Hydration failed because the server rendered HTML didn't match the client` + 에디터가 깜빡이며 다시 렌더링됨.

**원인**: 서버와 클라이언트 첫 렌더의 입력(콘텐츠, 확장 스키마 또는 외곽 UI)이 다릅니다.
내용이 같은 객체를 새로 생성하는 것만으로는 셸 HTML이 달라지지 않습니다.

**해결**: 서버에서 읽어 전달한 같은 초기 문서와 스키마로 시작하세요. 로컬 저장 초안은
마운트 후 불러오고, 필요한 경우 `onCreate`로 받은 인스턴스에서 `editor.commands.setContent(doc)`를 호출하세요.
자세한 동작은 [SSR](/ssr)을 참고하세요.

## `window is not defined` / `document is not defined`

**증상**: Next.js 빌드·서버 렌더 중 `ReferenceError`.

**원인**: 모듈의 최상위 코드나 렌더 중에 브라우저 객체를 읽거나, 브라우저 전용
컴포넌트를 SSR하는 경우입니다. `Editor`/`Viewer`를 Server Component에서
직렬화 가능한 props로 렌더링하는 것 자체는 원인이 아닙니다.

**해결**: 브라우저 객체를 쓰는 작업은 클라이언트 래퍼의 effect 또는 이벤트 콜백으로
옮기세요. Next에서 브라우저 전용 이미지 캔버스는 클라이언트 래퍼 안에서
`next/dynamic`의 `{ ssr: false }`로 분리할 수 있습니다.
본문 에디터는 그대로 두어 정적 셸을 유지하세요.

## 스타일이 적용되지 않음

**증상**: 에디터는 뜨는데 테마 없이 밋밋하게 보임.

**원인 1**: CSS import 누락. 패키지별 진입점에서 한 번 import해야 합니다.

```tsx
import '@inkio/editor/style.css'; // 클래식 프리셋이면 '@inkio/simple/style.css'
```

**원인 2**: `minimal.css`는 기본 토큰과 구조만 제공하고 전체 외형은 포함하지 않습니다.
별도의 스타일을 구성하지 않았다면 `style.css`를 쓰세요.
자세한 계약은 [컴포넌트 → CSS](/components#css) 참고.

**원인 3**: 본문 루트에만 변수를 지정해 `body` 포털의 색만 다릅니다. 포털에도
[CSS 변수를 지정](/components#css-변수와-포털)하세요. 이미지 편집기를 단독으로
쓸 때는 [공통 CSS 토큰이 필요](/image-editor#설치와-css)합니다.

## 번들이 갑자기 커짐

**증상**: 클라이언트 JS가 수백 KB 증가.

**원인 1**: 마크다운 subpath를 클라이언트 컴포넌트 모듈 레벨에서 import.
`remark/unified`가 클라이언트 번들에 딸려옵니다 (루트에서는 re-export하지
않으므로 루트 import는 실패합니다).

```tsx
// Before: 클라이언트 번들에 remark 포함
import { parseMarkdown } from '@inkio/editor/markdown';
const content = parseMarkdown(src); // HTML이 아니라 문서 JSON을 반환

// 클라이언트에서 가져오기 버튼을 눌렀을 때만 Markdown 청크 다운로드
async function onImport(src: string) {
  const { parseMarkdown } = await import('@inkio/editor/markdown');
  return parseMarkdown(src);
}
```

**원인 2**: classic 용도에 notion-like 프리셋 사용. `@inkio/simple`이
classic UI에 맞습니다. 저장소에서는 `pnpm build:packages` 후 `pnpm package:budgets`로 패키지 크기와 프리셋별 소비 번들을 확인하세요.

## Tiptap 관련 타입·런타임 충돌

**증상**: `Duplicate Tiptap instance`, 확장 인식 실패, 원인 불명 오동작.

**원인**: `@tiptap/*` 패키지를 직접 설치해서 Inkio 내장 런타임과 별개
복사본이 생겼습니다.

**해결**: 직접 설치한 `@tiptap/*`를 지우세요. 꼭 직접 조합해야 하면
버전을 Inkio 의존과 맞추세요. [확장 → 커스텀 확장](/extensions#커스텀-확장) 참고.

## 협업 상태가 `connecting`에서 안 넘어감

**증상**: `useInkioCollaborativeEditor`의 `status`가 계속 `connecting`.

**해결**: `http://`가 아니라 `ws://`(운영은 `wss://`)를 사용하고 포트와 경로를 확인하세요.
기본 Nest 실행은 `/collab`, 단독·분리 sync 실행은 `/`입니다.

```tsx
useInkioCollaborativeEditor({
  docId,
  url: 'ws://127.0.0.1:3123/collab', // 기본 Nest 실행
  token: () => getDocumentToken(docId), // 앱이 현재 로그인 사용자의 문서 토큰을 발급
});
```

`unauthorized`라면 해당 문서의 토큰과 ACL을 확인하세요. 토큰 발급·권한 조회·스냅샷 저장소
장애도 이 상태로 표시될 수 있으며 일시 실패는 백오프로 재시도합니다. 명시적 거부는
토큰을 갱신하세요. 이 상태에서는 편집할 수 없습니다.

자세한 내용은 [실시간 협업](/collaboration) 참고.

휴대폰에서 `127.0.0.1`은 개발 PC가 아니라 휴대폰 자신입니다. 기기에서 접속 가능한
서버 주소를 사용하고, 앱이 HTTPS라면 WebSocket도 `wss://`로 연결하세요.
